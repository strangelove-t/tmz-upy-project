# Handoff de desarrollo - 2026-10-06

## Resumen

El repositorio contiene un MVP local en Python y Streamlit para importar por
lote respuestas de Microsoft Forms, separar información identificativa, guardar
respuestas auditables y calcular nueve áreas de tamizaje mediante reglas
configurables. El instrumento es orientativo y no constituye un diagnóstico.

La implementación está preparada y probada, pero no se ha ejecutado ninguna
importación real. No existe `data/tamizaje.db` al momento de este handoff.

## Confidencialidad obligatoria

El archivo local de respuestas contiene:

- línea 1: encabezados;
- líneas 2-15: 14 registros de prueba autorizados para desarrollo;
- línea 16 en adelante: información real, sensible y confidencial.

Los CSV/XLSX de `data/`, bases SQLite y exportaciones están ignorados por Git.
No deben copiarse respuestas reales a fixtures, logs, documentación, issues,
commits, capturas o mensajes. La aplicación excluye automáticamente las 14
filas de prueba cuando se selecciona el modo de importación real.

## Estado funcional

### Cuestionario

- Fuente canónica: PDF v1.2 en `docs/`.
- 100 preguntas y cinco columnas administrativas.
- 105 de 105 encabezados aprobados.
- 56 campos clasificados como sensibles.
- `DC01` y `DC03` son opcionales.
- El cambio de “semestre” a “cuatrimestre” en `PE02` está documentado en
  `docs/incidents/2026-10-06-pe02-periodo-academico.md`.
- Las variantes históricas autorizadas están en
  `config/questionnaire_aliases.csv`; no existe coincidencia difusa.

### Importación y persistencia

- Detección segura de UTF-8, UTF-8 con BOM y CP1252.
- Detección y validación de separador, encabezados y anchura de filas.
- SHA-256 evita reimportar el mismo archivo.
- `ADM_EMAIL` identifica al estudiante después de normalizar Unicode,
  espacios y mayúsculas/minúsculas.
- `students` almacena correo, nombre, carrera y grupo.
- `submissions` almacena identificador de Forms, fechas, línea de origen,
  vigencia y marca de envío duplicado.
- `responses` almacena `QuestionCode`, valores original/normalizado y marca de
  sensibilidad; no mezcla campos `ADM_*`.
- Un segundo envío del mismo correo se conserva, queda no vigente y se marca
  para revisión.
- Todo se ejecuta en una transacción; cualquier fallo revierte el lote completo.

### Scoring configurable

- Versión activa: `0.2`.
- Nueve áreas y 64 reactivos cuantitativos.
- 314 combinaciones pregunta-respuesta configuradas.
- Todos los pesos de v0.2 son `1`.
- No existe puntaje global individual.
- `100` significa mayor fortaleza o menor dificultad reportada.
- Verde desde `70`, amarillo desde `40`, rojo por debajo de `40`; los umbrales
  pertenecen a cada área y no están codificados en Python.
- `CF05 = No aplica` se excluye del numerador, denominador y conteo aplicable.
- Una respuesta faltante o desconocida deja el área incompleta y nunca recibe
  un valor inferido.
- `area_results` conserva precisión completa y usa la clave envío + área +
  versión. Distintas versiones pueden coexistir.

Archivos de configuración:

- `config/parameters.yaml`: versión activa y límites de escala.
- `config/areas.csv`: áreas, umbrales y mínimo válido.
- `config/area_items.csv`: reactivos y pesos por área.
- `config/scoring_options.csv`: valores corregidos, alias y exclusiones.
- `config/questionnaire.csv`: contrato canónico del formulario.

Para cambiar reglas, crear filas con una versión nueva y cambiar
`active_scoring_version`. No modificar resultados históricos ni reciclar un
número de versión con otra semántica.

## Arquitectura relevante

- `app.py`: carga de configuración, previsualización y confirmación local.
- `src/tamizaje/importers.py`: lectura segura y selección de filas.
- `src/tamizaje/questionnaire.py`: catálogo y mapeo exacto de encabezados.
- `src/tamizaje/database.py`: esquema y persistencia transaccional.
- `src/tamizaje/scoring_config.py`: carga y validación cruzada de catálogos.
- `src/tamizaje/scoring.py`: cálculo puro de áreas.
- `tests/`: pruebas sintéticas; nunca contienen datos institucionales reales.

Las especificaciones y planes ejecutados están en `docs/superpowers/`. El
handoff técnico extenso original permanece en
`docs/Handoff_Tamizaje_UPY_App_Local.md`.

## Preparación local

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
python -m pytest
python -m ruff check .
python -m streamlit run app.py
```

En Windows se puede usar `.venv\Scripts\Activate.ps1` y posteriormente
`run_windows.bat`.

## Cómo realizar la primera importación real

1. Trabajar en una computadora institucional cifrada y autorizada.
2. Ejecutar primero las pruebas y revisar que la configuración cargue sin error.
3. Iniciar Streamlit y seleccionar el CSV original desde la interfaz.
4. Desactivar el modo seguro; la previsualización excluirá líneas 2-15.
5. Revisar únicamente conteos, mapeo y advertencias; no compartir capturas con
   respuestas.
6. Marcar la confirmación de autorización y ejecutar la importación.
7. Respaldar `data/tamizaje.db` sólo en almacenamiento institucional autorizado.

No ejecutar la primera importación real como parte de pruebas automatizadas.
